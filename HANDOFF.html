3. Project description

Bread Log is a personal sourdough notebook for one baker, used mostly on an Android phone in the kitchen. It began in 2023 as a copy-pasted ChatGPT calculator whose database save never worked. In this session it was rebuilt: Express 5 API, Postgres, vanilla ES-module front end, no build step.

The owner is getting back into baking, lives in a cold house, and is buying a starter warmer. A key goal is seeing how temperature affects starter activity. Hosting must be free or very cheap.

  • Calculator: baker's percentages; start from target dough weight or flour on hand; live weights; tap to tick ingredients off; save as recipe.
  • Bake-day timer: tap steps (autolyse, mix, folds, shape, fridge, oven, out), editable times, undo, fold reminder, screen wake lock. Finishing derives bulk, proof and bake minutes.
  • Starter tracker: feedings with ratio, temperature, warmer yes/no, peak time and rise %. Live "since feeding" clock, and a scatter chart of hours-to-peak vs temperature, warmer vs counter.
  • Bake log: timeline by month, ratings, notes, photos; each bake keeps a snapshot of its formula.
  • Compare any two bakes side by side, with differences highlighted.
  • Backups: JSON export/restore and a bakes CSV.
  • PWA: installable on Android, offline reads, launcher shortcuts.
  • Sign-in: one password (APP_PASSWORD), signed cookie for 180 days. It's mandatory in the cloud; with no password set, the cloud copy refuses to serve data.

API (JSON, camelCase; every route except health and session requires sign-in when a password is set):

  • GET /api/health, GET /api/session, POST /api/login, POST /api/logout
  • /api/recipes, /api/bakes, /api/starters: list / get / create / update (full PUT) / delete. /api/feedings: get / create / update / delete.
  • POST /api/bakes/:id/photos (raw image body, ?w=&h=), GET|DELETE /api/photos/:id
  • GET /api/export, GET /api/export/bakes.csv, POST /api/import[?photos=keep] (replaces everything)

PUT is a full replace. A bake update that omits status or events resets them to done and []. Clients send the whole object (see bake-form.js and timer.js).

8. Conventions and gotchas

  • snake_case ↔ camelCase happens only in each route's toApi() and params. The 2023 app's save bug was exactly this mismatch.
  • New migration: add server/migrations/006_name.js exporting the SQL string, append ['006_name.sql', m006] to index.js, never edit an applied one. A test checks the list. Migrations must be JS modules because Vercel only bundles imported files (the .sql files went missing in the first deploy).
  • New front-end JS file: add it to SHELL in public/sw.js and bump VERSION. A test checks the list.
  • Use fill(el, …), not el.replaceChildren(…). Views use cond && node, and replaceChildren would print "false". Build DOM with h(); don't use innerHTML with user text.
  • Keep the math pure (calc.js, timeline.js: no DOM, no fetch) and covered by node --test.
  • Formula fields come from FORMULA_KEYS/formulaOf() in calc.js. Add new formula fields there.
  • Vercel quirks: the root server.js must import 'express'; / reaches Express, which redirects to /index.html; express.static does nothing in the cloud; request bodies max out at 4.5 MB (photos are resized in the browser to about 1600 px first); migrations use DATABASE_URL_UNPOOLED because the advisory lock needs a real session.
  • Design: an "enamelware kitchen" palette (tokens at the top of app.css). Crust brown is reserved for numbers you weigh, times and ratings. Fonts: Bricolage Grotesque (display and numbers) and Atkinson Hyperlegible (body). Phone-first, bottom tab bar under 640 px, dark mode supported. Chart colours were checked for colour-blind separation: warmer #b5702a/#bf7a2a, counter #2f6db5/#4f8bd3.
  • Copy style: plain, sentence case, active verbs ("Log feeding", "Start a bake now"). Errors say what to do.
  • Commits: one focused commit per feature on main, with a descriptive body. Don't push, deploy or change Vercel settings without the owner's go-ahead.
